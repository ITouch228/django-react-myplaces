# Архитектура

## Общая схема

```text
Browser -> React 18 / TypeScript / Vite
               |
               | REST + JWT
               v
           Django / DRF
               |
               +--> SQLite (текущая версия)
               |
               +--> Place -> Check -> CheckItem
Browser -> Leaflet / OpenStreetMap tiles / Nominatim
```

Приложение состоит из независимых `frontend/` и `backend/`, соединённых REST API. Docker Compose нужен для локального запуска; документация собирается отдельно в Nginx-контейнере.

## Модель

- `Place`: название, адрес, широта, долгота, владелец.
- `Check`: место, владелец, дата посещения, комментарий.
- `CheckItem`: позиция, цена в `DecimalField`, необязательная оценка 1-5.
- `Place.avg_rating`: средняя оценка **позиций** всех чеков.
- `Place.avg_price`: средняя цена **позиции**, не средний чек.
- `Place.total_checks`: количество чеков.
- `Check.total`: сумма цен позиций через `Decimal`.

Места и чеки фильтруются по владельцу. Сериализатор проверяет принадлежность места при привязке чека. PATCH с полем `items` заменяет все позиции; без `items` сохраняет существующие.

Список мест использует SQL-агрегации и `prefetch_related` для снижения количества запросов.

## Нерешённые вопросы

- Единая PostgreSQL-модель и миграция существующей SQLite без потери данных.
- Отдельные сериализаторы краткого списка и подробной карточки.
- Индексы и пространственный поиск при росте числа мест.
- Файловое хранилище для фото чеков и блюд.
- Наблюдаемость, backup/restore и полноценный деплой.

Подробности интерфейсов см. в [HTTP API](api.md), последовательность работ в [плане](roadmap.md).
