# HTTP API

База для локального запуска: `http://localhost:8072/api/`.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| POST | `register/` | Регистрация, выдача JWT |
| POST | `token/` | Получение access/refresh JWT |
| POST | `token/refresh/` | Обновление access |
| GET | `user/` | Текущий пользователь |
| GET/POST | `places/` | Список своих мест / создание |
| GET/PATCH/DELETE | `places/{id}/` | Карточка, изменение, удаление |
| GET | `places/nearby/?lat=&lng=&radius=` | Личные места в радиусе, км |
| GET/POST | `checks/` | Свои чеки / создание с позициями |
| GET/PATCH/DELETE | `checks/{id}/` | Чтение и изменение чека |
| POST | `checks/{id}/add_item/` | Добавление позиции |
| GET/PATCH/DELETE | `check-items/{id}/` | Операции с позицией |

Кроме регистрации и выдачи токена, защищённые маршруты требуют `Authorization: Bearer <access>`. Анонимный пользователь не получает чужие данные.

## Редактирование сохранённого места

`PATCH /api/places/{id}/` обновляет поля только принадлежащего текущему пользователю места.

```json
{
  "name": "Кофейня у парка",
  "address": "Новый адрес",
  "latitude": 55.7558,
  "longitude": 37.6173
}
```

Возвращается обновлённый объект места (HTTP 200), при некорректных координатах HTTP 400 с ошибками полей, при попытке изменить чужое место HTTP 404. ID места и связанные чеки при изменении не пересоздаются. Дополнительных миграций для существующей модели не требуется.

## Пример создания чека

```json
{
  "place": 1,
  "visited_at": "2026-11-13",
  "comment": "Ужин",
  "items": [
    {"item_name": "Паста", "price": "540.50", "rating": 5},
    {"item_name": "Чай", "price": "160.00", "rating": 4}
  ]
}
```

`PATCH /checks/{id}/` без `items` изменяет только переданные поля; с `items` заменяет все позиции. Поддерживается оценка 1-5, цена должна быть неотрицательной.

`nearby` принимает широту [-90;90], долготу [-180;180] и положительный радиус не более 1000 км. Некорректные параметры возвращают 400.

!!! note "Контракт стоимости"
    В текущем API `avg_price` обозначает среднюю цену позиции, а не средний чек. Не переименовывайте значение без версии API или согласованного обновления клиента.

## Каталог мест (UX-02)

Поля `Place`: `category` (значения `cafe`, `restaurant`, `bar`, `bakery`, `other`), `visit_status` (`want` или `visited`), `is_favorite` (boolean). Они доступны в GET/list, POST и PATCH.

```json
{"category": "cafe", "visit_status": "want", "is_favorite": true}
```

Некорректные значения дают HTTP 400; изменение чужого места HTTP 404. Миграция `0003_place_catalog_fields` сохраняет существующие записи с умолчаниями `other`, `visited`, `false`.


## Количество в позициях чека (CHECK-01)

У каждой позиции есть `quantity` (целое 1–100000, по умолчанию 1 для старых записей). Поле `price` сохраняет смысл **цены за единицу**. API возвращает вычисляемое `line_total = price × quantity`, а `Check.total` равен сумме всех `line_total`.

При POST и PATCH передавайте цену десятичной строкой, не JS float:

```json
{
  "item_name": "Кофе",
  "price": "150.50",
  "quantity": 3,
  "rating": 5
}
```

Значения `price`, `line_total`, `total` сериализуются десятичными строками с 2 знаками. Пример: `"451.50"`. Отсутствующее `quantity` означает 1 для обратной совместимости. Недопустимое количество или цена возвращают HTTP 400. Миграция `0004_checkitem_quantity` выполняется **после `0003_place_catalog_fields`**; существующие чеки и суммы сохраняются.
