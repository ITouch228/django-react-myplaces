# Дорожная карта MyPlaces

Актуально: 13 ноября 2026 года. Источник статуса: код основной ветки `main`. Незавершённые изменения отражены отдельно. Разработка в коротких ветках **от актуального main**, без PR; тесты и документы обновляются **в той же ветке**, ручные `rebase` и `merge --no-ff`.

## Цель продукта

Личный дневник заведений: быстро сохранить место на карте, находить собственные места, фиксировать визиты, отдельные блюда и расходы, сравнивать впечатления и смотреть статистику. Приложение должно оставаться удобным с телефона. Приоритет: качество ввода и сохранность данных раньше сложных функций.

## Ближайшая последовательность

1. **UX-01 завершён в main**: форма добавления места и пользовательская документация.
2. **QA-01, текущая ветка**: расширенные компонентные тесты и обязательный CI gate. Перед merge проверить зелёный Jenkins на последнем SHA.
3. **UX-02 и UX-03**: категории, избранное и редактирование карточек с миграциями.
4. **API-01**: разделение краткого списка и деталей для будущего роста данных.
5. **DATA-01**: перенос на PostgreSQL со сценариями backup/restore до каких-либо опасных миграций.
6. **UX-04, CHECK-01, MEDIA-01**: пользовательские функции и медиа.
7. **ANALYTICS-01**: статистика, когда модель чека и цены стабилизирована.

Реальный порядок может уточняться после тестирования; **не реализовывать всё в одной ветке**.

## Definition of Done для каждой ветки

- Ветка создана непосредственно от актуального `main`; никаких PR и автоматического merge.
- Функции и состояния ошибок задокументированы в MkDocs **вместе с изменением кода**. Статусы `main` и ветки не смешиваются.
- Тесты логики, API/контрактов и изменённых пользовательских сценариев добавлены или аргументированно описаны ограничения.
- Jenkins зелёный на **последнем SHA**, `mkdocs build --strict` и проверки линтеров пройдены.
- Общий [чек-лист](testing.md#перед-merge) дополнен только новыми сценариями; ручная приёмка на ПК и телефоне.
- После `git rebase main` повторно проверить новый SHA и только затем вручную `git merge --no-ff` в main. Прогнать CI main и удалить ветку.
- Не удалять действующие базы, не выполнять разрушительные миграции без проверенного восстановления.

## Принципы архитектуры

Используем Django/DRF + React/TypeScript без лишних микросервисов. Для денег `Decimal`, для доступа фильтрация по владельцу и тесты, для UI явные состояния загрузки, пустых списков и ошибок. Не вводим OCR, общий доступ и сложную аналитику раньше надёжного CRUD и резервного копирования.
