# Дорожная карта MyPlaces

Обновлено 13 ноября 2026 года. Состояние описывает основную ветку `main`; эта документационная ветка ещё требует ручного rebase/merge и проверки Jenkins. Pull Request не используем.

## Реализовано

- Django 6.1, DRF, JWT, React 18, TypeScript, Leaflet + OpenStreetMap.
- Личные места, чеки с позициями, ценами и оценками 1-5; поиск по своим местам и геокодинг.
- Проверка владельца при создании/изменении чека, транзакционное редактирование вложенных позиций.
- Агрегирование рейтингов и цен в SQL, предзагрузка связанных данных.
- Валидация цены, координат и радиуса; `Decimal` для сумм.
- GitHub Actions CI: Python lint/types/tests и frontend lint/build/test command.
- SQLite как текущая база данных. PostgreSQL пока не внедрён.

## Этапы развития

| Этап | Приоритет | Содержание | Критерий готовности |
| --- | --- | --- | --- |
| 0. Документация и единый Jenkins | P0 | MkDocs Material, статический сайт, Jenkinsfile, отдельный MyPlaces job на общем контроллере | Зелёный Jenkins на последнем SHA; MkDocs strict, запуск docs на 8093 |
| 1. Запуск и надёжность | P0 | Починить Docker-порты, smoke старт Django, healthcheck; backup SQLite перед миграцией | Docker с нуля поднимает backend/frontend, нет ERR_CONNECTION_REFUSED |
| 2. PostgreSQL | P1 | PostgreSQL 16, конфиг среды, миграция данных SQLite, backup/restore, отдельная test DB | Восстановление реальных данных в тестовом окружении проверено |
| 3. Модель места | P1 | Категории, избранное, статусы «посещено/хочу», личная оценка места, заметки | API + unit/integration тесты, доступ только владельцу |
| 4. Навигация | P1 | Адаптивный layout, вкладки Карта, Мои места, Чеки, Статистика | Удобный мобильный экран, полная навигация |
| 5. Каталог и карта | P1 | Поиск нескольких совпадений, фильтры, сортировка, карточки и маркеры, добавление без prompt | Сохранять и находить место можно за несколько действий |
| 6. Чеки и блюда | P1 | Количество и сумма позиции, дата, редактирование, фотографии блюд и сканов | Чек сохраняется и редактируется без потери данных |
| 7. Аналитика | P2 | Траты за период, средний чек, топ заведений/блюд, экспорт CSV/JSON | Суммы совпадают с исходными чеками |
| 8. Качество и продакшен | P1 до релиза | React-тесты, E2E, rate limits, стабильный deploy, HTTPS и backup | Успешный smoke и тест восстановления данных |
| 9. Расширенные функции | P3 | QR/OCR чеков, повторяющиеся блюда, статистика цен, PWA, совместные списки | Только после стабильной базы и удобного MVP |

## Ближайший практический маршрут

1. Слить документацию и подготовить MyPlaces job на общем Jenkins.
2. Проверить полную сборку, Docker-порты и запуск на хосте.
3. Обеспечить тестирование пользовательского сценария, добавить React component tests.
4. Спланировать миграцию на PostgreSQL только после резервной копии SQLite.
5. Реализовать «Мои места», категории, избранное и удобную карту.
6. Перейти к фото чеков, расширенным оценкам и аналитике.

## Что не следует делать сейчас

- Не писать микросервисы и не менять стек ради архитектурной сложности.
- Не внедрять OCR до появления стабильной формы ручного ввода чека.
- Не менять схему или удалять SQLite без проверенного переноса данных.
- Не считать отсутствие frontend-тестов успешным полноценным покрытием: `--passWithNoTests` - временная мера.

После каждого этапа обновляйте документ и [единые критерии приёмки](testing.md#перед-merge).
