# Тестирование

## Backend, Python 3.12

### Windows PowerShell

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
$env:SECRET_KEY = "local-ci-only-not-for-production"
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\ruff.exe format --check .
.\.venv\Scripts\mypy.exe .
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

### Linux Bash

```bash
cd backend
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt -r requirements-dev.txt
export SECRET_KEY="local-ci-only-not-for-production"
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/mypy .
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test
```

`manage.py test` создаёт отдельную тестовую базу Django, не используйте рабочие данные для ручного тестирования.

## Frontend

```sh
cd frontend
npm ci
npm run lint
npm run build
npm run test:ci
```

!!! note "Текущий уровень покрытия"
    `npm run test:ci` запускает реальные Vitest-тесты и **завершается ошибкой при отсутствии тестов**. Проверяются поиск, сортировка, выбор и состояния пустого списка, а также валидация, отправка, отмена и блокировка формы создания места. Полный browser E2E и проверки реального Leaflet пока не реализованы.

## Документация

```sh
python -m pip install -r docs/requirements.txt
python -m mkdocs build --strict
```

Панель «Мои места»: при любом непустом поисковом запросе показывается ровно одна кнопка «Сбросить поиск», даже если совпадений нет. При пустом запросе кнопки нет. Компонентный тест проверяет оба состояния.

## Регистрация и анимации

- Регистрация: при вводе пароля из 1-4 символов сразу появляется ошибка; при 5 и более она исчезает.
- Повтор пароля: ошибка несовпадения появляется при вводе и исчезает при исправлении.
- Проверить корректное и некорректное имя (включая кириллицу), необязательный email и валидацию адреса.
- Не отправлять запрос при ошибках; при валидном вводе отправлять один запрос; во время загрузки блокировать повторную отправку.
- Ошибку `username` от Django REST Framework показать под именем; ошибку сети и `non_field_errors` показать отдельным уведомлением.
- Проверить регистрацию и вход на ПК и телефоне, анимацию появления, фокус, ошибки и состояние загрузки; включить `prefers-reduced-motion: reduce` и убедиться, что декоративная анимация отключена.
- Не возвращать последовательные задержки появления карточек чеков.

## Hotfix: CI, геолокация и название вкладки

- `App.test.tsx`: не искать устаревшие тексты «Вход» и «Регистрация». Проверять актуальные элементы страницы входа по доступной роли: заголовок «С возвращением», кнопку «Войти», ссылку «Зарегистрироваться».
- Открыть карту по HTTP в локальной сети, нажать «Моё местоположение»: уведомление о необходимости HTTPS должно показывать крестик «Закрыть уведомление о геолокации» и кнопку «Повторить».
- Закрыть уведомление крестиком: карта остаётся интерактивной, сообщение исчезает. Повторное нажатие GPS должно вновь отображать ошибку, если HTTPS всё ещё недоступен.
- Проверить название вкладки браузера `MyPlaces` на страницах входа, регистрации и карты.
- Проверить `npm run lint`, `npm run build`, `npm run test:ci` в Jenkins на итоговом SHA ветки. Важный регрессионный случай: условный JSX блок геолокации должен корректно закрываться `)}`; общий код проверки имени, сортировки и координат вынесен из React-компонентов, чтобы не возникало предупреждений React Fast Refresh.

## Перед merge

- Проверить актуальный SHA ветки и зелёные backend, frontend, docs проверки.
- Повторить основной сценарий: вход, создание места, создание чека с несколькими позициями, изменение и удаление.
- Проверить новую форму добавления места: клик по карте открывает окно с координатами; название обязательно, пробелы обрезаются, название длиной более 200 символов отклоняется, адрес необязателен; отмена/крестик/Escape не создают запись; при сохранении кнопки блокируются; ошибка API показывает сообщение без потери ввода; успешный POST показывает новый маркер и запись в панели. Проверить на телефоне, включая появление клавиатуры.
- Проверить карту, фильтрацию собственных мест и отсутствие доступа к чужим данным.
- Проверить стартовое положение карты: при одном сохранённом месте центр и zoom 15; при нескольких местах все маркеры попадают в видимую область; когда мест нет, отображается нейтральный обзор. При разрешённой геолокации после загрузки GPS карта центрируется на пользователе, но только если пользователь ещё не двигал карту, не нажимал на неё и не выбирал место через поиск/сайдбар. При недоступном GPS остаётся обзор собственных мест. Кнопка «Моё местоположение» работает независимо от стартовой логики.
- На телефоне проверить одновременно видимые кнопки «Мои места» слева снизу и «Моё местоположение» справа снизу, включая маленький экран, экранную панель браузера и вырезы/навигационную область. Убедиться, что они доступны поверх Leaflet и не за пределами видимой высоты. Кнопка GPS инициирует запрос только по нажатию; при HTTPS/разрешении центрирует карту, при отказе выводит сообщение. При LAN HTTP явно сообщается, что требуется HTTPS, без молчаливого сбоя.
- Проверить панель «Мои места»: открытие/закрытие, пустое состояние, поиск по названию и адресу, сброс запроса (ровно одна кнопка «Сбросить поиск» при непустом запросе), сортировку, переход к **нужному** маркеру, открытие popup и ссылку «Подробнее». Поиск своих мест должен отсутствовать в строке поиска адреса над картой. На телефоне проверить нижнюю панель, прокрутку длинного списка и отсутствие перекрытия элементов управления.
- Проверить чеки: разворачивание и сворачивание, редактирование и удаление чека, добавление/изменение/удаление позиции, длинные названия и адаптацию на телефоне. Нет последовательных анимаций появления и скачков карточек.
- Проверить запуск Docker Compose и правильные порты.
- Если менялась схема БД, проверить миграции и сохранность существующих данных.
- После merge повторить CI на `main`.

Это единый чек-лист для текущих изменений. По мере реализации фото и статистики расширять его, не плодить отдельные чек-листы.

## Обязательные frontend-тесты в CI

Jenkins и GitHub Actions запускают **одну и ту же команду**:

```sh
cd frontend
npm ci
npm run test:ci
```

Vitest обнаруживает файлы `*.test.ts` и `*.test.tsx`. Компонентные тесты используют окружение `jsdom`, React Testing Library и MemoryRouter. Пустой набор тестов или упавший тест означает красную сборку. Мокировать запросы или `MapContainer` в следующих тестах нужно локально и детерминированно; не обращаться к реальному Nominatim в CI.

При проверке ветки с компонентными тестами обязательно проверить: тесты запускаются в Jenkins на последнем SHA, весь frontend gate зелёный, в логах есть исполняемые кейсы `CreatePlaceDialog` и `PlacesPanel`; ручной smoke карты на ПК и телефоне не заменён тестами компонентов.
